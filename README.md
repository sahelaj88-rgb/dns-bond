# DNS Bond

روی **مستر ایران** یک پراکسی SOCKS5 محلی با پورت انتخابی داری. برنامه یا outbound پنل خودت به آن وصل می‌شود. دو مستر یک اتصال TCP را بین مسیرهای فعال تقسیم می‌کنند؛ مستر خارج اتصال مقصد را باز می‌کند. همهٔ مسیرهایی که به همان خروجی می‌رسند IP عمومی همان خروجی را دارند. هر جفت ایران و خارج دامنه و کلید جدا دارد.

## اول نقش سرورها را مشخص کن

|سرور|کار|
|---|---|
|مستر ایران|پراکسی محلی، مسیر DNS خودش، تجمیع دانلود و پخش آپلود، نگهداری فایل DNS|
|کمکی ایران|پایش resolver از شبکهٔ خودش و ورودی TCP مخصوص مستر ایران|
|مستر خارج|ورودی DNS جفت خودش، تجمیع آپلود و پخش دانلود، اتصال نهایی به سایت|
|کمکی خارج|ورودی DNS دامنهٔ خودش و هدایت تونل به مستر خارج|

می‌توانی با فقط دو مستر شروع کنی. برای اضافه‌کردن یک مسیر دیگر، یک جفت کمکی اضافه کن. مثال‌های راهنما برای یک پروفایل در هر ماشین لینوکسی‌اند. نام دامنه، آدرس و نام کاربر SSH را با مال خودت عوض کن.

## ۱. کد و موتور تونل را روی هر سرور بگذار

از لینوکس با **Python 3.11 یا جدیدتر**، OpenSSL و Git استفاده کن. مثال مناسب Ubuntu 24.04 است. مخزن خصوصی است؛ برای clone باید دسترسی خواندن همین مخزن را داشته باشی. می‌توانی کد را روی کامپیوتر خودت بگیری و از طریق SSH در همان مسیر کپی کنی.

```sh
git clone https://github.com/sahelaj88-rgb/dns-bond.git
sudo cp -R dns-bond /opt/dns-bond
cd /opt/dns-bond
python3 --version
sudo useradd --system --create-home --home-dir /var/lib/dns-bond --shell /bin/sh dnsbond
```

اگر کاربر dnsbond از نصب قبلی وجود دارد، دستور آخر را رد کن. روی **ایران** دستور اول و روی **خارج** دستور دوم زیر را اجرا کن.

```sh
sudo python3 install_engine.py client
sudo python3 install_engine.py server
```

دانلود از ریلیز رسمی MasterDnsVPN نسخهٔ ثابت `v2026.11.18.210322-7198b45` است. نصب‌کننده SHA-256 آرشیو را با مقدار ثبت‌شده بررسی می‌کند. برای سرور بدون دسترسی GitHub، روی لینوکس هم‌معماری دستور را با `--directory ./bin` اجرا کن و باینری حاصل را در `/usr/local/bin` مقصد بگذار. معماری‌های amd64 و arm64 پشتیبانی می‌شوند.

## ۲. دامنهٔ هر جفت را تنظیم کن

برای مثال، برای جفت اول روی zone خودت در Cloudflare این دو رکورد را بساز. در ستون Content مقدار واقعی را بگذار.

|Type|Name|Content|Proxy|
|---|---|---|---|
|A|ns1|IPv4 عمومی سرور خارجِ همین جفت|DNS only|
|NS|tun1|ns1.example.com|—|

نامی که در نصب این جفت می‌دهی `tun1.example.com` است. برای جفت دوم می‌توانی دامنهٔ ثبت‌شدهٔ دیگری داشته باشی، مثلاً `tun2.example.net` با رکورد A برای `ns2.example.net` و رکورد NS برای `tun2`. سرور کمکی خارج هم باید IP خودِ آن جفت را در رکورد A داشته باشد. اگر ایران چند ورودی می‌بیند، هر جفت باید نام و کلید متناظر خودش را استفاده کند.

روی هر سرور **خارج** و فایروال ارائه‌دهنده، ورود **UDP/53 و TCP/53** را مجاز کن. اگر از قبل DNS عمومی روی همان IP و پورت فعال است، برای این سرویس IP یا میزبان جدا در نظر بگیر. ورودی عمومی به موتور محلی MasterDnsVPN روی UDP/15453 متصل می‌شود. سرویس آن موتور روی loopback می‌ماند. روی **ایران** برای خود پروکسی به بازکردن پورت ۵۳ نیازی نیست.

برای بررسی واگذاری در یک شبکه با دسترسی DNS:

```sh
dig NS tun1.example.com
dig A ns1.example.com
```

خروجی باید نام سرور و IP جفت انتخابی را نشان بدهد. ممکن است انتشار رکورد زمان ببرد.

## ۳. برای دو مستر گواهی بساز

روی یک ماشین مدیریتی مطمئن در پوشهٔ کد اجرا کن.

```sh
sh certificates.sh ./bond-keys
```

فایل‌های زیر را با SSH به سرورهای مربوط منتقل کن. بعد از ساخت پروفایل در مرحلهٔ بعد، آن‌ها را در `/var/lib/dns-bond/node/` قرار بده و مالکیتشان را به `dnsbond` بده.

|کجا|فایل‌های موردنیاز|
|---|---|
|مستر ایران|ca.crt، entry.crt، entry.key|
|مستر خارج|ca.crt، exit.crt، exit.key|
|سرورهای کمکی|گواهی مستر لازم ندارند|

فایل `ca.key` نزد مدیر می‌ماند. تاریخ اعتبار گواهی‌های مستر یک سال است. این گواهی‌ها اتصال بین دو مستر را حتی هنگام عبور از کمکی‌ها احراز هویت می‌کنند.

## ۴. خارج را راه بینداز

روی هر خارج، از `/opt/dns-bond` اجرا کن:

```sh
sudo -u dnsbond python3 setup_node.py /var/lib/dns-bond/node
```

ابتدا `outside` و سپس `master` یا `helper` را انتخاب کن. دامنهٔ اختصاصی همان جفت را وارد کن. برای پورت تجمیع می‌توانی پیش‌فرض 7443 را بپذیری. روی کمکی خارج، آدرس مستر خارج و همان پورت را بده. روی مستر خارج، دسترسی TCP/7443 را برای کمکی‌های خارج مجاز کن. کلید ۳۲ کاراکتری و فایل `pair.json` با دسترسی خصوصی در پوشهٔ پروفایل ساخته می‌شوند. تنظیم دوباره را در پوشهٔ جدید انجام بده تا کلید قبلی حفظ شود.

فایل `pair.json` را از طریق SSH به ایرانِ همان جفت برسان. روش اختیاری، ساخت کد عضویت یک‌بارمصرفِ ۱۵ دقیقه‌ای است. روی خارج:

```sh
sudo -u dnsbond python3 /opt/dns-bond/join.py invite /var/lib/dns-bond/node
```

روی ایران، اگر SSH از قبل با کلید و host key شناخته‌شده به حساب دارای دسترسی به آن پروفایل وصل می‌شود:

```sh
python3 /opt/dns-bond/join.py redeem USER@OUTSIDE /var/lib/dns-bond/node pair.json
```

کد را در پرسش مخفی وارد کن. این روش به یک مسیر مدیریت SSH فعال نیاز دارد. در زمان قطع آن مسیر از فایل جفتی استفاده کن که قبلاً امن منتقل کرده‌ای.

## ۵. ایران را راه بینداز

یک فایل `resolvers.txt` بساز. هر خط یک آدرس دقیق IPv4 یا IPv6 از سرویس‌های DNS قابل استفاده و مجاز برای شبکه‌ات است. خط خالی و توضیح بعد از # پذیرفته می‌شود. فایل با حداکثر ۳۰٬۰۰۰ IP یکتا خوانده می‌شود. روی هر ایران ابتدا یک نسخهٔ اولیهٔ این فایل و `pair.json` همان جفت را در محلی قابل خواندن برای کاربر dnsbond بگذار.

```sh
cd /opt/dns-bond
sudo -u dnsbond python3 setup_node.py /var/lib/dns-bond/node
```

۱. گزینهٔ `iran` و نقش را انتخاب کن. دامنه و مسیر فایل جفت را بده. برنامه تطابق نام و کلید را بررسی می‌کند.

۲. برای پورت اتصال به تونل، پیش‌فرض 17001 مناسب است. روی کمکی ایران، IP قابل دسترس از مستر ایران را بده و دسترسی TCP این پورت را در فایروال به مستر محدود کن.

۳. حالت انتقال `auto`، `udp` یا `tcp` را انتخاب کن. در حالت خودکار هر resolver ابتدا با UDP بررسی می‌شود؛ اگر پاسخی معتبر ندهد، TCP امتحان می‌شود. مسیر فعال آخرین انتقال موفق را اول امتحان می‌کند. ارتباط **resolver با سرور authoritative** را خود resolver انتخاب می‌کند. هر دو نوع ورودی در سمت خارج فعال‌اند.

۴. روی مستر ایران، آدرس کمکی‌ها را مثل `10.20.0.4:17001,10.20.0.5:17001` وارد کن. برای شروع بدون کمکی `-` بزن. مسیر مستقیم مستر خودکار اضافه می‌شود.

۵. برای توزیع خودکار فایل، مقصدهای SSH کمکی‌ها را مانند `helper1:/var/lib/dns-bond/node,helper2:/var/lib/dns-bond/node` بده. نام‌ها باید از حساب dnsbond روی مستر ایران با SSH مبتنی بر کلید و host key از قبل تأییدشده قابل دسترسی باشند. برای اجرای بدون کمکی `-` بده. سرویس تغییر محتوای فایل را بررسی می‌کند و آن را با تعویض اتمیک در کمکی‌ها می‌گذارد؛ مقصد ناموفق دوباره امتحان می‌شود.

۶. پورت SOCKS5 مستر ایران را بده، مثلاً 1080 یا 2080. آدرس همیشه `127.0.0.1` است. در پنل خودت یک **outbound SOCKS** به این آدرس و پورت بده، سپس inbound دلخواه را به همان outbound مسیریابی کن. لینک گوشی از inbound خودت می‌آید. پنل و پراکسی باید در یک فضای شبکه باشند؛ داخل کانتینر جدا، loopback به خود کانتینر اشاره می‌کند. ورودی SOCKS پروژه فعلاً فرمان **CONNECT** را پشتیبانی می‌کند. حمل UDP/53 برای خود تونل، از UDP ASSOCIATE برنامه‌های گوشی جداست.

## ۶. سرویس را روشن کن

روی هر مستر گواهی‌های مرحلهٔ ۳ را به پروفایل منتقل کن. فایل‌های کلید باید فقط برای حساب سرویس قابل خواندن باشند. روی هر چهار نقش:

```sh
sudo cp /opt/dns-bond/dns-bond.service /etc/systemd/system/dns-bond.service
sudo systemctl daemon-reload
sudo systemctl enable --now dns-bond
sudo journalctl -u dns-bond -n 40
```

اول خارج‌ها و بعد ایران‌ها را روشن کن. برنامه ممکن است تا پیدا شدن اولین resolver سالم دوباره تست MTU انجام دهد. لاگ موتور بالادستی ممکن است حاوی کلید باشد. برای پشتیبانی لاگ را پس از پاک‌کردن کلید به اشتراک بگذار.

روی مستر ایران، پورت را مطابق نصب خودت جایگزین کن:

```sh
curl --noproxy '' --socks5-hostname 127.0.0.1:1080 https://api.ipify.org
```

باید IP خروجی مستر خارج را ببینی. در مرحلهٔ بعد یک فایل شناخته‌شده را از پروکسی بگیر و اندازه و هش آن را مقایسه کن. برای سنجش اثر مسیر دوم، همان فایل و سرور مقصد را با یک جفت و سپس با دو جفت هم‌زمان آزمایش کن.

## ۷. پایش و تغییر فهرست

روی مستر ایران فایل جدید را ابتدا با نام موقت در همان پوشه کپی کن و با `mv` جایگزین `resolvers.txt` کن. در هر ایران، پایشگر فایل را در دور بعد می‌خواند. هر بار یک درخواست TXT تازه به دامنهٔ همان جفت می‌فرستد و پاسخ امضاشده با کلید جفت را بررسی می‌کند. پاسخ cacheشده برای یک درخواست قبلی قبول نمی‌شود. سپس خود MasterDnsVPN ظرفیت واقعی payload و MTU مسیر فعال را می‌سنجد.

نرخ پیش‌فرض شروع تست ۱۰۰ در ثانیه، سقف انتخابی ۱۵۰ و سقف تست هم‌زمان ۶۴ است. برای تغییر نرخ، به آرگومان‌های `pool.py` در `services.json` مقدار `"--rate", "150"` اضافه کن و سرویس را restart کن. timeout و تکرار روی انتقال دوم بر تعداد واقعی DNS query اثر دارند. زیر بار پراکسی نرخ پایش کاهش پیدا می‌کند. هر گره هشت جایگاه برای resolverهای فعال دارد. پس از سه خطا resolver از مجموعهٔ سالم کنار می‌رود و در دورهای بعد دوباره بررسی می‌شود. خواندن فایل ۳۰ هزار ورودی آزمایش شده؛ نرخ پایدار شبکه و سرعت ۵۰۰–۶۰۰ کیلوبایت‌برثانیه به آزمایش روی سرورهای واقعی نیاز دارند.

## آزمون‌های توسعه

```sh
python3 -m unittest -v
```

آزمون‌ها ترتیب تکه‌ها، عبور از پنجرهٔ دریافت، انتخاب مجدد TCP با قطع UDP، تطبیق کلید و دامنه، فایل ۳۰ هزار ورودی و ادامهٔ انتقال پس از قطع یک مسیر را می‌سنجند. نمونهٔ آموزشی `python3 demo.py` فقط به سرویس محلی نمایشی خودش وصل می‌شود؛ مسیر اجرای سروری `run_node.py` است.

منابع: [موتور MasterDnsVPN](https://github.com/masterking32/MasterDnsVPN)، [حالت‌های انتقال WhiteDNS Desktop](https://github.com/WhiteDNS/WhiteDNS-Desktop). کد پایشگر و تجمیع در این مخزن مستقل نوشته شده است.

برای آزمون یکپارچه با **باینری‌های واقعی**، هر دو باینری را روی یک میزبان تست لینوکسی در PATH بگذار و اجرا کن:

```sh
python3 checks/network.py
```

آزمون چهار نقش و دو دامنهٔ آزمایشی را روی loopback می‌سازد، فایل مبدا و پاسخ SOCKS را بایت‌به‌بایت مقایسه می‌کند و یک دانلود دیگر را تنها از مسیر کمکی TCP انجام می‌دهد. برای اجرا با کاربر عادی، در این آزمون پورت‌های بالاتر از ۱۰۲۴ جای پورت ۵۳ استفاده می‌شوند. کلیدهای موقت بعد از اتمام پاک می‌شوند. برای نتیجهٔ عملی شبکهٔ ایران هنوز باید واگذاری DNS، دسترسی به UDP/TCP پورت ۵۳ و سرعت پایدار را از همان سرورها اندازه گرفت.
