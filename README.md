# DNS Bond

این نسخهٔ اولیه برای آزمایش مرتب‌سازی داده بین دو مستر است. هر دو سمت روی همان کامپیوتر اجرا می‌شوند. برای این آزمایش دامنه، سرور خریداری‌شده یا دسترسی روت لازم نیست.

## آزمایش در سه قدم

۱. روی لینوکس یا مک با Python 3.11 یا جدیدتر، یک ترمینال در پوشهٔ پروژه باز کنید. آزمون‌ها را اجرا کنید.

```sh
python3 -m unittest -v
```

باید در انتها عبارت OK را ببینید. آزمون، یک جریان بزرگ‌تر از سه پنجرهٔ دریافت را از سه مسیر عبور می‌دهد و بایت‌ها را در هر دو جهت مقایسه می‌کند. آزمون جداگانه دریافت خارج از ترتیب و تکراری را بررسی می‌کند.

۲. نمونه را روشن کنید و ترمینال را باز بگذارید.

```sh
python3 demo.py
```

۳. در ترمینال دوم این درخواست را بفرستید.

```sh
curl --noproxy '' --socks5 127.0.0.1:1080 http://127.0.0.1:18080/
```

پاسخ مورد انتظار `dns-bond local transfer OK` است. با Ctrl+C در ترمینال اول نمونه را متوقف کنید. اگر خطای Address already in use دیدید، برنامهٔ دیگری یکی از پورت‌های ۱۰۸۰ یا ۱۸۰۸۰ را اشغال کرده است.

## مسیر داده در نمونه

ورودی SOCKS5 درخواست اتصال IPv4 به سرویس HTTP آزمایشی محلی را می‌پذیرد. برای هر جهت سه مسیر محلی مستقل ساخته می‌شود. فرستنده تکه‌ها را شماره‌گذاری می‌کند. گیرنده تکه‌ها را به ترتیب تحویل می‌دهد و پس از هر ۶۴ تکه رسید می‌فرستد. این سقف، حافظهٔ موردنیاز برای تکه‌های نامرتب را محدود می‌کند. آزمایش روی سوکت محلی است و سرعت یا پینگ تونل DNS را اندازه نمی‌گیرد.

## معماری نسخهٔ سروری در دست توسعه

- نصب‌کننده ابتدا ایران یا خارج و سپس مستر یا کمکی بودن را می‌پرسد.
- مستر ایران فایل DNS را توزیع می‌کند. هر گره ایرانی resolverها را از شبکهٔ خودش تا دامنهٔ تونل می‌سنجد و فهرست فعال خود را نگه می‌دارد.
- مستر خارج اتصال به مقصد را باز می‌کند تا IP خروجی ثابت بماند. گره‌های کمکی تونل‌های مستقل بین دو کشور را حمل می‌کنند.
- برای پنل سنایی، ورودی VLESS کانفیگ گوشی را می‌دهد. قانون مسیریابی آن ورودی را به خروجی SOCKS5 روی مستر ایران وصل خواهد کرد.
- اتصال واقعی MasterDnsVPN، تعریف رکوردهای A و NS در Cloudflare، تحویل کلید، عضویت گره‌ها، پایش خودکار و ادامهٔ جریان پس از قطع یک مسیر، مراحل بعدی توسعه هستند. نمونهٔ فعلی برای نصب روی سرور عمومی آماده نیست.
